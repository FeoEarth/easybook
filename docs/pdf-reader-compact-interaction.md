# Compact PDF interaction

PDF-only UI update on top of the build96 loading fix. The loading/byte-read/Worker/rendering configuration and attachment protocols are unchanged.

The page pill opens a single-row anchored navigation surface (previous, nonwrapping label, numeric-keyboard input, total, next, commit). Invalid or out-of-range input stays open with a short message; a valid jump and previous/next actions dismiss it. The search surface has an inline search icon, explicit clear, compact current/total and result navigation, and Done. Existing PDF.js find events are used. One panel state owns search, jump and file menu/info; outside/back/Escape closes it, blurs inputs, clears the shield and restores reading. The initial unready reader disables navigation/search controls until handlers and document exist.

Float geometry is clamped to the current visual viewport and updated on keyboard/viewport resize. The title is flex-bounded with an ellipsis and fixed chevron. PDF-scoped input styling overrides the global yellow focus outline without changing editor/settings inputs. Existing page content/pinch/scroll remains unchanged, shield prevents underlying touch while a panel is open. Compact popovers use existing fade/position/scale entry animation; no claim is made that unspecified details exactly reproduce iOS.

Android reuses the existing GlassSurface recipe. Slots 6 and 7 add page navigation and search alongside the existing six PDF surfaces. Only these two projected WebViews are focusable. An origin-scoped, length-bounded edit/submit protocol updates original PDF-only input controls; it does not expose attachments or credentials. The isolated projection retains real input/IME, focus/selection and local text when an older render arrives, and defers replacements during composition. Closing detaches its keyboard. Web retains CSS glass fallback. No shader, refraction, backdrop sampling, blur or highlight parameters were changed.

Validation: focused non-browser component checks cover page validation/commit, panel exclusion, search clear, back/outside dismiss, native projection edit/submit/stale-update focus preservation, and existing real PDF.js first-page pixels/filename/close-reopen checks. Android compile/signature must pass before merge. No emulator, UI automation or broad regression. Real Android IME, composition, small-screen positioning, native glass alignment, animations and touch feel remain unverified. Cloudflare is not deployed; production Web stays at its existing deployment until separately requested.
