# Scheduled workers

Payment Worker retains the one-minute cron; actual payment scans run every five minutes when idle, every minute while unpaid orders or scanner backlog exist. Collection Worker has no independent cron after a staged transition. Its private RPC entrypoint evaluates existing signed/broadcast transactions on even-minute ticks and discovers new jobs on 15-minute ticks only when enabled and a signer exists. Existing per-chain leases select the oldest eligible chain, replacing wall-clock modulo rotation. Manual authenticated endpoints remain available. Backup and sync schedules are unchanged. Backup now accepts up to 256 ordinary tables and batches metadata reads, retaining atomic data/schema validation and attachment verification. Deployment tests must pass before production promotion; the transitional cron stays active until the scheduler deploy succeeds. Check R2 status/latest-success.json and status/latest.json following the next backup trigger; do not treat deployment alone as a successful backup.
