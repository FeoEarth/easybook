# Easybook 0.8.0 — Architecture decision and audit (phase 1)
Date: 2026-10-24. GitHub baseline: 781257bdf1600d8d9d88fa03e78dde52e33f7d50. Status: design only; no runtime verification.
## Evidence and existing system
Android Java WebView shell, local SQLite NoteRepository, NativeSync, AttachmentStore, CredentialVault and SecurityManager; bundled Tiptap 3.32.0 + ProseMirror editor; Web Worker UI generated from Android HTML; Cloudflare Worker API, D1 notes/folders, private R2 attachments. GitHub main latest commit adds offline rich editing, nested tasks and private attachment sync. Cloudflare account inventory confirms easybook-sync Worker, easybook-data D1 and easybook-attachments R2; this inventory does NOT verify live binding wiring, data integrity or successful sync.
Source: README.md; package.json; editor/rich-editor.js; worker/index.mjs; worker/schema.sql; worker/attachments.mjs; app/src/main/java/com/feoearth/easybook/{NativeSync,NoteRepository}.java; docs/native-security-stage-2.md.
## Verified code-level concerns
- Body is still TEXT HTML with `<!--easybook-rich-v1-->` marker, DOMPurify and legacy Markdown-to-HTML path; JSON is not authoritative.
- Editor attachment inserts a paragraph containing `attachment:<sha256>` link, not a first-class image/media node.
- Web and Android share generated UI but have different local persistence/credential boundaries; need semantic parity tests, not UI similarity alone.
- Worker note API accepts a 60,000-character string body and 260 KB request; no versioned JSON schema validation.
- GET notes uses id pagination, not incremental change feed; repeated full scans and conflict handling need testing.
- Folder write uses INSERT ... DO NOTHING; rename/move/delete and tombstone semantics require dedicated contract.
- R2 upload is immutable content-hash addressed, 5 MiB cap, JSON/base64 transport; reference lifecycle, orphan GC, upload resume and media rendering need design.
- API Access-Control-Allow-Origin:* with bearer workspace token; analyze browser origin threat and XSS/CSP controls before changing.
- README still describes older preview workflow and says images not supported despite later 0.7 changes; documentation is stale.
## Decision ADR-001: canonical document
Use ProseMirror/Tiptap JSON as the ONLY canonical note body, with `schemaVersion:1` envelope and `doc:{type:"doc",content:[...]}`. Validate schema, allowed marks, nesting, attrs, node count and serialized byte size on client and server. Derive plain text/search preview and optional HTML view; never round-trip canonical HTML. No legacy migration/compatibility in test stage. Backup current remote data before any destructive deployment.
Supported nodes: paragraph, heading(level 1..3), text, bulletList, orderedList, listItem, taskList, taskItem(checked), blockquote, codeBlock, horizontalRule, hardBreak, image(assetId,alt,width,height), attachment(assetId,name,mime,size), and optional table after feasibility test. Marks: bold, italic, underline, strike, code, link (safe schemes). Task nesting has bounded depth and deterministic checked state. No arbitrary HTML, URL, or script attributes.
Example:
```json
{"schemaVersion":1,"doc":{"type":"doc","content":[{"type":"heading","attrs":{"level":1},"content":[{"type":"text","text":"Example"}]},{"type":"taskList","content":[{"type":"taskItem","attrs":{"checked":false},"content":[{"type":"paragraph","content":[{"type":"text","text":"Todo"}]}]},{"type":"image","attrs":{"assetId":"sha256:<digest>","alt":"Photo"}}]}]}}
```
## Decision ADR-002: sync and storage
D1 is authoritative for note envelope, revision, mutation ID, folder relationship, tombstone and attachment metadata/reference associations. R2 remains private object storage with workspace-scoped keys. Android SQLite and browser IndexedDB are offline caches plus mutation outbox; credentials stay native vault on Android. Keep per-note optimistic CAS and idempotency; introduce monotonic workspace change cursor (not ID cursor) for incremental pull, atomic mutation+revision+change-log writes, explicit 409 conflict-copy policy, and stable server timestamps. Upload content-hash-verified attachments before note commit; download on demand, verify digest and size, reference-count/mark-and-sweep garbage collection only after grace period. Prevent resurrection with tombstones; never delete remote objects on a note edit. Document consistency guarantees: eventual cross-device convergence, no realtime collaboration/CRDT in 0.8.0.
## Decision ADR-003: UI
iOS 26 Apple Notes is interaction inspiration, not a claim of identical native Android controls. Apple documented: folders/subfolders, pinning, list/gallery, formatting, collapsible headings, checklists, attachments, tags. Sources: https://support.apple.com/guide/iphone/organize-in-folders-ipha61270292/26/ios/26 ; https://support.apple.com/en-gb/118442 ; https://support.apple.com/en-ie/guide/iphone/iphedddbfdf9/26/ios/26 . Easybook-specific: Android native secure bridge, Cloudflare sync, conflict copies, offline outbox, R2 object model, content hashes. Do not imply Apple implements these mechanisms.
One direct editing surface (no required edit/preview mode switch), formatting bar, stable selection, IME composition safety, inline media, task indentation, accessible reduced-motion variants.
## Keep / rewrite / remove
Keep and harden: Android native shell, Keystore vault, origin-gated bridge, SQLite transactions, HTTPS fixed host transport, Worker/D1/R2 deployment model, CAS/idempotency, private attachments, existing tests.
Rewrite: canonical content serialization, editor/media nodes, folder operations, sync change feed, Web offline storage parity, attachment lifecycle, UI interactions and validation.
Remove after tests: rich-v1 HTML canonical marker, legacy Markdown import/renderer and dual edit/preview requirement, attachment-as-link representation. Do not remove old data or secrets as part of phase 1.
## Security boundaries and unresolved verification
Bearer token grants whole workspace; server stores SHA-256-derived workspace identifier, not E2EE. Android Keystore protects credentials, not note content; Web localStorage credential handling is different. Worker CORS wildcard and browser XSS deserve threat-model review; verify CSP and origin gate in built assets. R2 private bucket must not be exposed by public domain. Confirm Worker bindings and access restrictions read-only. Validate malformed JSON, unsafe URLs, MIME spoofing, decompression/oversize, replay, idempotency, cross-workspace attachment access, WebView bridge calls, token leakage and logging redaction.
