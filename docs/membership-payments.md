# 测试会籍与收款运维

当前价格为月度 1、季度（3 个月）2、半年 3、年度 5 USDT；均为单次购买，无权益，无自动扣款。永久套餐已下架，不再提供升级或剩余价值抵扣。任意档位均按全价购买，从当前时间和现有到期日中的较晚者开始，按 UTC 自然月累加对应月数。重复购买、跨档购买都不会重置或缩短有效期。历史已付款记录和其他账户已有永久权益保留。到账先计入余额，未能结算的款项保留余额，不自动退款。

## 付款确认流程

选择套餐时显示报价加载动画，旧报价立即失效；只有当前套餐报价成功后才允许点击支付。点击支付只预留 30 分钟的锁价订单，不扣余额。付款面板提供会员余额、链上转账两种方式，用户再确认。余额方式通过 `/orders/:id/pay` 明确扣款；链上方式通过 `/orders/:id/fund` 确认网络后显示收款码，仅以确认后入账的链上款项自动结算，不隐式消耗已有余额。少付可以追加，也可切换余额支付；取消记录的迟到账保护继续生效。

未确认付款方式的订单标记为 `unselected`，扫描器和数据库触发器都禁止自动结算。切换套餐会替换未确认订单，已经确认链上付款的订单必须完成或取消。订单金额不可修改，确认请求会核对显示的套餐和金额。部署前依次应用迁移至 `0028-membership-duration-only.sql`，同步部署主站和支付 Worker。

页面微交互使用原生 CSS 和 Web Animations：按压反馈、套餐回弹、金额更新、付款面板进退场、方式勾选、网络区域展开、复制成功和开通勾线。系统开启减少动态效果时取消位移、回弹和动画等待，保留状态文字。定时刷新时保持未变化的订单列表，避免重复入场。

付款成功时播放约 4.5 秒的全屏双侧彩带：仅对本页曾观察到的未支付订单转为已结算的状态触发一次，适用于余额支付和链上确认；初次载入及查看已支付历史不触发。彩带层不接收点击，不遮挡操作；切到后台、离开页面或开启减少动态效果时清理画布及动画。减少动态效果模式只显示付款成功文字提示。

Gas 预估：登录后 `GET /api/membership/gas?chainId=...` 读取已配置 RPC 的实时 `eth_gasPrice`，核对链 ID 并尝试备用节点。按普通 ERC-20 转账 65,000–100,000 Gas 给出原生币参考区间（AVAX/XPL/POL/ETH），30 秒缓存并合并并发请求。未连接付款钱包，无法按真实发送方余额和代币存储状态模拟交易；钱包最终报价优先。Arbitrum 另外读取 ArbGasInfo `getPricesInWei()` 的每字节价格，按 200–400 字节参考压缩体积估算 L1 数据费；该调用不可用时明确仅显示 L2 执行费。查询失败不阻止付款，切换网络丢弃旧请求；余额支付显示无需 Gas。

余额充值：`POST /api/membership/topups` 校验 1–999999999 的正整数 USDT 金额和可用网络，返回固定账户地址、二维码所需信息及到账进度起点，不创建会籍订单、不修改余额。输入金额为充值目标，实际链上任何正数转账均按原有扫描规则逐笔准确记账；少付可追加，多付全额入账。若存在已确认的会籍待付款单，保留到账优先结算规则，页面明确提示。`GET /topups/status?after=...` 仅汇总该账户起点之后的真实链上信用事件。

链上收款：`GET /api/membership/receipts` 按账户查询实际链上收据，同时包含余额账本产生的收款及余额账本上线前的历史直接付款；同一收据去重，以 `(created_at,chain_id,tx,log_index)` 游标每页 20 条分页。页面与会籍订单分为独立页签，记录实际收到金额、代币、网络、确认入账时间、区块、日志序号和交易哈希；后台赠送余额不计入链上记录。充值二维码路由 `?depositQr=1` 只读取当前登录账户的固定地址，无法指定其他用户地址。

## 当前测试钱包

测试钱包已按用户明确指定的 MetaMask Account 3（`m/44'/60'/0'/0/2`）核对。应用持有的扩展公钥属于父分支 `m/44'/60'/0'/0`。本地配置将 `MEMBERSHIP_ADDRESS_OFFSET` 设为 `2`，首单使用分支下的 `/3`，避免复用前三个钱包账户。具体地址和 xpub 仅保存在被 Git 忽略的 `.local-membership/wallet.json`，未写入源码。助记词、种子、私钥及 xprv 不存盘、不进入代码、日志或 Git。该钱包已在聊天中披露助记词，永久限定为测试用途。

数据库首次下单时固定钱包公钥哈希和地址偏移量。已有订单的库若更换这两个参数会拒绝分配新地址，防止静默切换钱包造成资金失配。商业上线使用新的自管钱包和独立、干净的支付数据，不直接替换测试数据库的 xpub。

## 本地模拟联调

需要 Node.js 24。已经准备好的本地公钥配置可直接运行：

```sh
npm run membership:config
npm run membership:demo
```

打开 `http://127.0.0.1:8789/`。服务器仅监听 loopback，使用独立的 `.local-membership/demo.sqlite`，不连接生产数据库。模拟 RPC 仅在本地工具内实现，不调用主网，不广播交易。可创建四链、四档订单，查看真实派生的地址、二维码及复制按钮，点击“模拟准确到账”验证完整扫描和会籍流程。只有本地工具提供 `/__simulate`，部署 Worker 不提供这个入口。

本地模拟页明确显示“模拟支付测试，请勿转账”；部署后的正常测试会员页显示真实付款地址和二维码，保留“测试阶段，会员暂无任何功能”的说明，不显示模拟到账按钮。二维码内容是订单收款地址，付款仍须核对页面的网络、代币合约与准确金额。

`.local-membership/env.json` 的模拟 RPC 为 `rpc.simulation.invalid`，不能用于部署。将模拟标志带到外部域名会被 API 拒绝；扫描模拟模式时必须显式注入本地 RPC。

钱包导出工具 `scripts/membership-wallet-export.mjs` 仅通过 stdin 接收助记词，公开参数为预期地址及从 0 开始的账户索引。它会校验助记词和地址，匹配后只导出公钥 JSON；输出文件已存在时不覆盖。不要将助记词作为命令行参数、环境变量、命令历史或源码传入。当前测试钱包不需要再次导出。

## 部署前准备

1. 新建隔离测试环境与独立数据库，不把测试配置部署到现有生产数据库。API、身份服务和支付 Worker 指向同一套测试账户数据库；安全恢复数据库须保持独立。应用现有账户迁移，再依次应用 `0023-membership.sql`、`0024-membership-scan-windows.sql`。部署配置遵循 Cloudflare 环境绑定规则：https://developers.cloudflare.com/d1/configuration/environments/ 。本轮未创建远端资源或执行远端迁移。
2. 设置 API 的 `MEMBERSHIP_XPUB`、`MEMBERSHIP_ADDRESS_OFFSET`；API 与支付 Worker 使用相同的 `MEMBERSHIP_NETWORKS`。正常部署不设置模拟标志，或设为 `MEMBERSHIP_SIMULATION=false`。RPC 若包含凭据，使用 Cloudflare secrets，不提交配置文件。
3. 网络配置字段为 `chainId`、`symbol`、`token`、`decimals`、`rpc`、`startBlock`、`finality:"finalized"`、`verified:true`。只有验证通过的网络才开启；`startBlock` 应在准备部署时重新取值，避免使用过期探测结果。
4. 先启用支付扫描 Worker，确认扫描游标追平，再开启 API 下单。关闭新单可用单链 `acceptOrders=false`，仍保留原订单扫描；移除网络配置会同时停止扫描。
5. Android 必须构建签名 APK，不能只 OTA 网页。会员 Activity 使用隔离 WebView，无原生 JS 桥；初始 native 授权换取 30 分钟会员专属 HttpOnly Cookie，原账户会话撤销后也失效。
6. 当前真实收款未启用，尚未进行真实转账或资金转出验收。商业上线另用新钱包，并补做真实小额付款及转出验证。

## 扫描、异常与恢复

每条链每轮最多两个基础 RPC 查询加五个日志批次；每批最多 64 个订单地址、100 个区块。通过 ERC-20 Transfer 的收款 topic 过滤地址，不扫描全链 USDT 交易。使用 finalized 区块日志；回滚交易不会产生已确认日志，无需逐笔查询回执。返回日志仍校验合约、地址、区块范围和结构。超出 1000 条日志的批次不推进，需要减小窗口或人工诊断。

扫描窗口保存地址快照及已完成的地址索引，所有快照地址扫描完成后才推进全链区块游标。中断后从持久化窗口继续，部分已入账交易可以安全重放。订单、收款与会籍流水通过原子事务保证同一日志只记一次。已结算和过期订单的地址也继续扫描，用于记录重复及迟到付款。

监控 `membership_scan_failed`、每条链游标延迟与异常 receipt。扫描落后超过五分钟暂停新单，保留订单查询。安全恢复锁阻止扫描继续。恢复支付库前必须核对地址分配索引和链上流水，不得恢复旧索引后直接重新分配地址。

核账联结 `membership_receipts`、`membership_orders` 和 `membership_changes`，通过 chain_id、tx、log_index 定位。仅 status=paid 对应自动权益。首版无退款后台或自动归集；异常付款需人工处理并另留审计。将完整支付表及 `membership_wallet_config` 导出 SQLite 后，`node scripts/membership-balances.mjs export.sqlite` 可只读查询当前余额及实际派生索引，不签名交易。资金归集另需各链 Gas。

## 验证与限制

- `npm run test:membership`：交易原子性、四链模拟 RPC、API 鉴权与 CSRF、跨账户隔离、会话撤销、幂等重试、金额异常、跨套餐累加续费规则、扫描分页与中断恢复、钱包配置保护，以及真实地址／二维码和复制功能。
- `npm test`：现有应用回归；另外运行账户和原生授权相关测试。
- Wrangler `deploy --dry-run`：检查 API、支付 Worker 的实际打包，不证明远端资源可用，也不会执行部署。
- Android 缺少 Gradle／SDK 时仅做静态与授权接口验证，不声称 APK 或实机流程已验收。

## 固定用户地址、余额及续费（账户地址版本）

迁移 `0026-membership-account-wallets.sql` 后，每个账户固定一个地址，四条链共用。现有用户采用其最早的收款地址；其余旧订单地址作为该用户的别名持续监控。旧订单表不删除，未付款旧订单归档为已取消，新订单存入 `membership_purchases`，避免旧表地址唯一约束影响重复购买。

所有允许代币的最终确认到账（包括少付、多付和无订单充值）按 6 位整数精度记入余额。余额足够时自动支付当前唯一待付款订单；没有订单时保留余额。单笔订单可跨四链追加付款。取消不扣余额、不执行链上退款。

固定地址无法证明转账原本属于已取消订单还是新订单。保守保护规则：手动取消或到期后建立取消标记；标记未解除时，下一笔到账留在余额中，同时自动取消新待付款订单。用户看到到账余额后，显式点击“用余额继续”创建订单，才解除这次保护；取消前已有余额也允许显式确认使用。退款由人工处理，系统不自动签名。

纯时长续费：月度、季度、半年、年度均按全价购买，不区分升降档。每次从 `max(当前时间, 现有到期日)` 追加所购月数；例如半年+半年+年度累加为 24 个月。历史抵扣时段归档保留，不参与新订单。

新增接口：`GET /api/membership/quote?plan=...`、`POST /api/membership/orders/:id/cancel`。状态接口返回固定地址、余额和取消保护状态；订单返回总价、追加月数、需付、已到账及待追加金额。地址、余额、订单支付和会籍变更均按账户归属隔离；余额采用文本整数和事务 CAS，重复日志、并发取消与支付不能重复入账或扣费。

显式余额支付：选择套餐后可点击“使用余额支付”，或在待付款面板中使用余额支付该笔订单。创建订单传 `useBalance:true`，已有订单使用 `POST /api/membership/orders/:id/pay`。余额不足时拒绝扣款；余额支付不依赖 RPC 扫描健康度，也不消耗链上 Gas。用户主动支付时，在同一会籍结算事务中确认取消保护并扣款，避免人工充值后因保护标记无法支付。支付完成面板立即显示结果，不等待链上扫描刷新。

改价使用统一套餐配置及价格版本号。前端展示、服务端报价和余额扣款均读取同一配置。旧未付款报价在改价时取消；旧页面缺少或携带过期价格版本的购买请求会被拒绝，提示刷新。既有已付款订单按实际历史支付价格保留，不随改价重估。
