# Attachments, tables and fast mode

The common attachment menu now offers Photos and videos, Files, Table, Link and Checklist. Android API 33+ uses the system Photo Picker for images/video with the platform multi-select limit and no media-library permission. Older systems or unavailable picker fall back to a media-filtered SAF picker; Files always uses unrestricted multi-select ACTION_OPEN_DOCUMENT. ClipData and single URI results are deduplicated and streamed to existing private AttachmentStore originals, with bounded existing 1 GB import. Temporary persistable grants are released after copying. Cancellation/errors clear picker selection state; no external filesystem paths are used. Web uses separate image/video and unrestricted file inputs.

Video uses the existing attachment node, with inline controls and existing fullscreen/file actions. No additional binary model or cloud upload protocol was introduced; compression, originals and 50 MB cloud cap stay unchanged.

Tables use Tiptap 3.32.0 standard table/tableRow/tableCell/tableHeader nodes. Each cell stores colspan, rowspan, colwidth and align with block content and normal text marks. Default insertion is 2x2 without headers, in the current selection. The same attachment menu exposes row/column insertion/deletion and whole-table deletion only while a table is selected. Standard table paste handling receives sanitized HTML. A horizontally scrollable wrapper contains wide tables; existing caret/IME reveal logic is reused.

Android and Web/Worker consume identical contract assets. Shared and Java validators check table shape, spans, widths and rectangular grids (up to 200 rows / 64 columns within existing document byte/node/depth limits). Existing JSON documents remain valid. SQLite and D1 continue storing the JSON envelope; no migrations, reset or deletion. Worker shared validation must be deployed so new tables are accepted. The current unchanged PDF UI modules are packaged with Worker HTML to avoid mismatching the previously deployed static vendor asset set. No PDF source, D1/R2 schema or attachment API changes.

Fast mode is per-device, off by default; settings flush pending notes before applying and reloading. Web persists it in localStorage; Android additionally stores it in private SharedPreferences and restores it before page scripts. Native glass Bridge requests are rejected while enabled, live native surfaces are detached, CSS blur/translucent material is replaced with opaque controls. Turning it off reloads normal adapters. No Shader or QWEA0 engine implementation is changed.

Focused validation: actual editor table insert/text marks/row-column operations/undo-redo, JSON round trip, IndexedDB close/reopen, canonical fixture and invalid grid rejection; Java unit check of the same fixture and identical schema assets; picker multi-select/URI/static routing; Web builds and Android release compile/signature. No emulator, UI automation or broad regression. Actual Photo Picker/SAF provider behavior, real SQLite/device cross-sync, inline video codecs, IME/caret feel and fast-mode performance remain unverified on a device.
