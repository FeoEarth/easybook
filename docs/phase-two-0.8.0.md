## Contract
`shared/document-contract.json` is byte-identical to Android's asset. `document.mjs` and native `DocumentModel` enforce the same node/attribute/mark rules, UTF-8 byte limit, depth and node count. Envelope: `{schemaVersion:1,doc:{type:'doc',content:[...]}}`. Supports all requested nodes/marks plus text, hardBreak, codeBlock. Asset references use `sha256:<64 lowercase hex>`. No arbitrary HTML or media URLs. Link schemes restricted to http, https, mailto. Invalid versions, structure, unsafe links or extra attributes are rejected; existing saved/editor content is never silently replaced by an empty document. JSON backups use easybook-json-v1; legacy backup import and canonical HTML/Markdown conversion are removed.

## Storage
Android keeps easybook-native.db and its existing credentials/settings, while JSON notes use a separate note_json_v1 record kind in the transactional records table, document object payloads, native revision, dirty state, persisted immutable outbox and workspace cursor. Web uses fresh IndexedDB easybook-json-v1, one atomic workspace snapshot for notes/folders/inflight/cursor, and revision CAS preventing stale tab overwrites. Legacy local stores and D1 notes remain untouched and are not read as canonical data. No old-data migration; connecting an old workspace shows only its new JSON notes. Native pairing keys remain in Keystore/CredentialVault and never enter the renderer; no remote secret or R2 reset. Security checkpoint support concerns credentials, not legacy HTML compatibility.

## Protocol
`PUT /api/notes/:uuid`: title, document, icon, favorite (existing favorite flag), pinned (independent pin flag), deleted (tombstone), folder_id, expected version, mutation UUID. version=0 creates; updates compare current version. D1 batch atomically performs CAS, receipt and read. Note triggers append a monotonic change cursor within the same transaction. Immutable workspace/mutation receipts replay original acknowledgements after later writes; changed payloads reusing a mutation are rejected. 409 yields current remote note; clients retain latest local content in a visible conflict copy. No clock-based last-writer-wins. `GET /api/notes?cursor=N` returns notes/cursor/hasMore. Cursor advances only after local atomic persistence. Deleted notes remain tombstones. No remote file deletion on note writes.

Dirty notes are a durable mutation queue; each immutable in-flight request is saved before transport, retained on failure and cleared transactionally with acknowledgement. Edits made during upload retain dirty state and adopt the acknowledged base version. Periodic/online/manual retry reuses persisted request. Folder management and attachment previews retain current scope; no complete UI redesign.
